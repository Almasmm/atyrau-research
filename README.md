## 🧭 О проекте

Проект выполняет **Assignment 1** как четыре законченных эмпирических исследования, привязанных к Атырау. Это **не план и не шаблон** — каждый кейс содержит собранные данные, обученные модели, посчитанные метрики, отчёт, презентацию и выполненный Jupyter-ноутбук.

| № | Кейс | Тема | Задача ML |
|---|------|------|-----------|
| **01** | `01_Air_Pollution` | Оценка загрязнения воздуха | Анализ временных рядов, сезонность, превышения ПДК (WHO) |
| **02** | `02_Air_Quality_Prediction` | Прогноз качества воздуха | Прогнозирование PM/загрязнителей (baseline vs ML) |
| **03** | `03_Water_Monitoring` | Мониторинг уровня воды (р. Урал) | Регрессия/прогноз уровня, replay-валидация |
| **04** | `04_Vehicle_Classification` | Классификация транспорта | Компьютерное зрение, классификация изображений |

> ⚠️ **Важно:** два «воздушных» кейса (01 и 02) используют **общий источник данных** и разные производные таблицы. Это не четыре независимых набора данных.

**Текущий общий статус — `PARTIAL`.** Все четыре эксперимента проведены, но для каждого есть незакрытые условия задания (см. [дорожную карту](#-как-довести-проект-до-максимума--дорожная-карта)). Именно эти пробелы — ваша зона роста.

## 🎯 Как довести проект до максимума — дорожная карта

> Цель: закрыть незакрытые условия задания и поднять реальные метрики. Работайте по приоритетам ⭐ (высокий → низкий). После каждого изменения — перезапуск `reproduce.py --mode science` и обновление метрик в отчётах.

### 🟥 Кейс 02 — Прогноз качества воздуха `⭐⭐⭐ максимальный потенциал`

**Проблема:** ML не превзошла наивный persistence (MAE 3.686).

- [ ] **Признаки:** лаги (t-1…t-24), скользящие средние, час/день/сезон, погода (температура, ветер, влажность), праздники/отопительный сезон.
- [ ] **Модели:** градиентный бустинг (XGBoost / LightGBM), SARIMA/SARIMAX, Prophet, LSTM/GRU — сравнить по единому протоколу.
- [ ] **Валидация:** строго `TimeSeriesSplit` (walk-forward), без утечки будущего; доверительные интервалы.
- [ ] **Мультигоризонт:** прогноз на +1ч, +6ч, +24ч.
- [ ] **Критерий успеха:** MAE/RMSE ниже persistence на тесте + значимость улучшения.

### 🟥 Кейс 03 — Мониторинг уровня воды `⭐⭐⭐`

**Проблема:** Ridge хуже persistence на 0.072 см.

- [ ] Лаговые признаки, сезонная декомпозиция, учёт осадков/снеготаяния (внешние гидро/метео ряды).
- [ ] Модели: Gradient Boosting, SARIMAX, LSTM; ансамбли.
- [ ] Расширить исторический ряд (длиннее окно → устойчивее обучение).
- [ ] Multi-step прогноз + сценарий половодья; анализ ошибок на пиках.
- [ ] **Критерий успеха:** стабильно побить persistence на нескольких горизонтах.

### 🟥 Кейс 04 — Классификация транспорта `⭐⭐⭐`

**Проблема:** macro-F1 0.488 на COCO; нет данных Атырау.

- [ ] **Данные Атырау:** легально собрать/разметить видео или фото местного трафика (ключевое условие задания).
- [ ] **CNN / transfer learning:** ResNet/EfficientNet/MobileNet, аугментации, fine-tuning вместо логистической регрессии.
- [ ] **Детекция:** перейти к YOLO/Faster R-CNN для подсчёта и классификации в кадре.
- [ ] Балансировка классов, per-class метрики, confusion matrix, калибровка.
- [ ] **Критерий успеха:** macro-F1 ≥ 0.80 и валидный тест на данных Атырау.

### 🟧 Кейс 01 — Загрязнение воздуха `⭐⭐`

- [ ] Подтвердить у поставщика **каналы, калибровку и временные метки** станций.
- [ ] Сезонная декомпозиция, зимние пики/инверсии, превышения порогов **WHO** с подсчётом exceedance-дней.
- [ ] Корреляция с погодой/промышленностью; **атрибуция источников** (транспорт/энергетика/отопление) — пока отсутствует.
- [ ] Расширить на сравнение городов Казахстана (Алматы, Астана, Темиртау и т.д.) по заданию.
- [ ] Карты AQI (опционально), доказательные рекомендации на 5–10 лет.

### 🟦 Кросс-проектные улучшения `⭐`

- [ ] **Данные:** где возможно — заменить офлайн-архивы на живые источники (AirKaz, Kazhydromet, IQAir) с фиксацией новых SHA-256.

## 🔁 Воспроизведение экспериментов

Проверенная среда: **Windows 11, Python 3.12.14, CPU**. Точные версии — в `requirements.txt` и `environment.json`.

| Режим | Команда | Что делает |
|-------|---------|------------|
| **verify** | `python scripts/reproduce.py --mode verify` | Проверяет сохранённые результаты **без обучения** (быстро) |
| **science** | `python scripts/reproduce.py --mode science --case all` | Повторяет подготовку данных, обучение, оценку, ноутбуки |
| **full** | `python scripts/reproduce.py --mode full --case all` | Дополнительно пересоздаёт DOCX/PPTX/PDF и проверки пакета |

- Ограничить одним кейсом: `--case 01` (или `02`/`03`/`04`). Воздух №02 зависит от подготовленных данных №01.
- **Проверка переносимости:** `python scripts/package_submission.py --retrain-check` — повторяет конвейеры в отдельной копии и сверяет метрики; результат пишется в `UNPACKED_REPRODUCTION_CHECK.json`.
- **Экспорт Office (PDF из DOCX/PPTX):** требует локальный Microsoft Word/PowerPoint (COM) и **PowerShell 7**; на системе без Office выполните экспорт в среде с Office.
- **Пересборка PPTX:** нужен поставляемый пакет `@oai/artifact-tool` и Node (переменные `ARTIFACT_TOOL_ENTRY`, `NODE_EXE`). Научный режим транспорта также требует **ffmpeg с H.264** в PATH.
- API-ключи не нужны; интернет понадобится, если отсутствуют исходные архивы (скрипт качает по опубликованным URL и сверяет SHA-256).

> 📌 На Windows предпочтителен Python-вход (`reproduce.py`); `reproduce.sh` нужен только для bash-оболочки.

## 👥 Рабочий процесс для команды

1. **Ветки:** работайте в отдельных ветках — `feature/02-xgboost`, `feature/04-cnn-atyrau` и т.п. Не коммитьте прямо в `main`.
2. **Окружение:** никогда не коммитьте `.venv/`, `_build/`, `_backups/` (уже в `.gitignore`). Новые зависимости → добавить в `requirements.txt` с точной версией.
3. **Данные:** новые снимки данных фиксируйте с SHA-256 в соответствующих `data_lock.json` / `SOURCE_REGISTER.csv`. Соблюдайте лицензии (некоммерческие/ShareAlike, где указано).
4. **Цикл изменения:**
   ```bash
   git checkout -b feature/<кейс>-<что>
   # правки в pipeline.py / код кейса
   python scripts/reproduce.py --mode science --case <NN>   # перепроверить метрики
   # обновить Report/Presentation/SUBMISSION_STATUS при изменении чисел
   git add -A && git commit -m "feat(<кейс>): краткое описание"
   git push -u origin feature/<кейс>-<что>
   # открыть Pull Request
   ```
5. **Правило:** метрики в отчётах и презентациях **всегда** должны совпадать с тем, что выдаёт `reproduce.py`. Расхождение = баг.
6. **Критерий «готово» для кейса:** пробел из дорожной карты закрыт → метрика улучшена и воспроизводима → документы обновлены → статус в `SUBMISSION_STATUS.md` поднят с PARTIAL.

## ❓ Открытые вопросы (FAQ)

**Почему статус PARTIAL, а не готово?**
Все эксперименты реальны и воспроизводимы, но у каждого кейса есть незакрытое условие задания (атрибуция источников, превышение baseline, данные Атырау и т.п.). Оформление файлов эти пробелы не закрывает — нужна содержательная доработка.

**С чего начать, чтобы быстрее всего поднять результат?**
Кейс 02 и 03 — там наивный baseline ещё не побит, вход низкий, потенциал высокий. Кейс 04 — нужен собственный датасет Атырау и CNN.

**Можно ли заменить офлайн-данные на живые?**
Да, желательно — AirKaz / Kazhydromet / IQAir для воздуха. Обязательно зафиксируйте новые SHA-256, чтобы сохранить воспроизводимость.

**Зачем два «воздушных» кейса (01 и 02)?**
Общий источник данных, но разные задачи: 01 — описательный анализ и риски, 02 — прогнозирование. Это одно происхождение данных, не два независимых набора.

**Как убедиться, что я ничего не сломал?**
`python scripts/reproduce.py --mode verify` сверит текущие результаты с зафиксированными. Для полной уверенности — `package_submission.py --retrain-check`.

## 🧱 Соглашения и дисциплина качества

- **Воспроизводимость прежде всего.** Любой результат должен пересчитываться из кода одной командой.
- **Фиксация происхождения.** Источник данных → SHA-256 → датасет → метрика. Разрывов в цепочке быть не должно.
- **Честные метрики.** Не подгоняйте числа под отчёт — обновляйте отчёт под числа.
- **Раскрытие ИИ-помощи** обязательно (`AI_USAGE_DISCLOSURE.md`). Оценку ставит преподаватель по своей рубрике — не обещайте баллы.
- **Защита самостоятельна.** Используйте `DEFENSE_GUIDE_RU.md` для подготовки.
