# Проверенное окружение

- ОС: Windows 11, версия ядра 10.0.26200. WSL Ubuntu доступен; использован для чтения занятых исходных документов.
- Python: 3.12.14, 64-bit, поставляемый Codex runtime. Модели работают на CPU.
- Ресурсы, измеренные при запуске: 24 логических CPU, 63,37 GiB RAM, более 1,2 TiB свободно на диске C.
- GPU определён через WSL nvidia-smi как NVIDIA GeForce RTX 5090 Laptop GPU, 24 463 MiB. Для результатов GPU не использовался и не требуется.
- Изолированные установки находятся в `project/.venv`, рядом с папкой пакета; venv читает базовые библиотеки runtime через `--system-site-packages`. Базовый и системный Python не изменялись. Для финального общего запуска установлен `PYTHONNOUSERSITE=1`, чтобы не использовать случайные библиотеки пользовательского site-packages. Дополнительно установлены недостающие platformdirs/pywin32 в этот venv.
- Версии основных библиотек зафиксированы в requirements.txt и environment.json. `pip check` выполнен успешно.
- Чистые kernels создаются через nbclient. Локальный kernelspec `atyrau` установлен только внутри `.venv/share/jupyter`. Notebook outputs сохраняются и не подменяются заранее написанными метриками.
- DOCX создаётся python-docx, PPTX — поставляемым Codex `@oai/artifact-tool` 2.8.59, Node 24.19.0. Генераторы включены. Chart values округлены до четырёх знаков в редактируемом Excel-снимке; полная точность сохранена в results.
- PDF отчётов и презентаций экспортированы локальным Microsoft Word и PowerPoint через COM из созданных файлов. Пользовательские исходные документы не изменялись. Поставляемый render_docx.py запускался, но не нашёл LibreOffice; отсутствие этого рендерера устранено экспортом через Office, а не объявлено успешным запуском render_docx.py.
- PDF растеризованы PyMuPDF для визуальной проверки. Первичные CSV/JSON и метрики проверяются отдельно: визуальная аккуратность не доказывает правильность вычислений.
- Транспортное demo кодируется ffmpeg, доступным в пользовательском PATH, и проверяется OpenCV. Требуется ffmpeg с H.264, при отсутствии нужно установить его отдельно в пользовательскую среду. Исходный ролик и лицензия указаны в кейсе.

## Перенос на другой компьютер

Для научных расчётов достаточно Python 3.12, зависимостей requirements.txt, ffmpeg и интернет-доступа для недостающих исходных файлов. Включённые разрешённые кеши сокращают загрузки. Полные гидрологические PDF не распространяются; числовой ряд и происхождение включены. `--download-water-sources` у scripts/reproduce.py повторяет извлечение с открытых PDF.

Для полного воспроизведения оформления требуется установленная среда Codex с приватным artifact-tool и Windows Office. Пути не зашиты в код под имя автора: определяются через Path.home(), местонахождение скриптов или переменные среды NODE_EXE, ARTIFACT_TOOL_ENTRY, PRESENTATION_SKILL_DIR и RUNTIME_PYTHON. Вне этой среды используйте режим science и перенесите этап полного экспорта в документированную среду. Полностью автономный Linux-экспорт DOCX/PPTX в PDF не заявляется.

Браузерный просмотр локального Notebook.html был заблокирован политикой URL браузера; обход не предпринимался. Успешное чистое исполнение, HTML-структура и встроенные графики проверены отдельно. Это ограничение записано как NOT_RUN для визуального HTML-просмотра.

Дополнение к экспорту: проверенная оболочка — PowerShell 7.6.5 из bundled runtime. Legacy Windows PowerShell 5.1 в составе общего subprocess-запуска зависал на первом Word ExportAsFixedFormat; прямой экспорт через PowerShell 7 прошёл. reproduce.py использует PowerShell 7; переопределение — POWERSHELL_EXE. Экспорт идёт в уникальный PDF внутри project/_build, затем результат копируется в пакет. Сам по себе уникальный PDF не устранял сбой старой оболочки. ffmpeg фактически: 8.1.2-full_build-www.gyan.dev, H.264 libx264.
